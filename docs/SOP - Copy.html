Standard Operating Procedure

SOP Internal DB App

Dokumen ini disusun untuk pengguna akhir berdasarkan fitur yang benar-benar tersedia di sumber kode aplikasi. Fokus SOP adalah penggunaan harian untuk login, dashboard, pengelolaan data aset, laporan, manajemen pengguna, pengaturan, dan proses administrasi yang dapat diakses melalui antarmuka web.

1. Ringkasan Dokumen

Tujuan SOP

1.1 Purpose

SOP ini menjelaskan langkah operasional yang dapat dilakukan pengguna pada Internal DB App. Seluruh prosedur disusun dari fitur yang terlihat di kode sumber dan halaman Blade yang tersedia.

1.2 Preconditions

  • Pengguna memiliki akun yang aktif.
  • Pengguna mengetahui peran aksesnya, misalnya pengguna biasa atau administrator.
  • Pengguna membuka aplikasi melalui browser web.

1.3 Steps

  1. Baca daftar isi untuk memilih proses yang diperlukan.
  2. Ikuti langkah pada setiap bagian sesuai fungsi yang ingin dijalankan.
  3. Gunakan placeholder gambar untuk melengkapi dokumentasi operasional saat tangkapan layar tersedia.

1.4 Expected Result

Pengguna dapat menjalankan fungsi sistem sesuai akses yang dimiliki tanpa perlu memahami detail teknis aplikasi.

1.5 Troubleshooting

  • Jika menu tidak muncul, periksa peran pengguna dan status login.
  • Jika halaman gagal dimuat, muat ulang browser atau login kembali.
  • Jika proses tidak tersimpan, pastikan isian wajib lengkap dan tidak ada pesan validasi.
2. Login

Prosedur Masuk ke Sistem

2.1 Purpose

Memungkinkan pengguna mengakses aplikasi dengan akun yang terdaftar.

2.2 Preconditions

  • Pengguna memiliki email dan kata sandi yang valid.
  • Browser dapat membuka halaman login.

2.3 Steps

  1. Buka halaman login aplikasi.
  2. Masukkan alamat email pada kolom Email Address.
  3. Masukkan kata sandi pada kolom Password.
  4. Klik tombol Login.
Placeholder gambar
  • Screen: Halaman login sebelum pengguna memasukkan kredensial.
  • Action: Pengguna meninjau form login dan mengisi email serta kata sandi.
  • Why: Menunjukkan lokasi field dan tombol Login agar pengguna akhir mudah mengikuti langkah masuk.
Placeholder gambar
  • Screen: Halaman login setelah tombol Login ditekan.
  • Action: Sistem memproses kredensial yang dimasukkan pengguna.
  • Why: Menunjukkan kondisi saat validasi login berjalan dan membantu dokumentasi bila terjadi pesan kesalahan.

2.4 Expected Result

Pengguna diarahkan ke dashboard setelah autentikasi berhasil.

2.5 Troubleshooting

  • Jika muncul pesan email atau password salah, periksa kembali data yang diinput.
  • Jika halaman kembali ke form login, pastikan akun memang aktif.
  • Jika browser menampilkan error sesi, muat ulang halaman lalu login kembali.
3. Logout

Prosedur Keluar dari Sistem

3.1 Purpose

Memutus sesi kerja pengguna saat selesai menggunakan aplikasi.

3.2 Preconditions

  • Pengguna sudah login.
  • Pengguna berada di halaman aplikasi utama.

3.3 Steps

  1. Buka menu pengguna atau menu keluar yang tersedia di antarmuka.
  2. Klik Logout.
  3. Tunggu hingga sistem kembali ke halaman login.
Placeholder gambar
  • Screen: Area menu pengguna atau tombol Logout pada tampilan aplikasi.
  • Action: Pengguna memilih Logout untuk mengakhiri sesi.
  • Why: Penting untuk memperlihatkan lokasi kontrol keluar agar proses terminasi sesi dapat diikuti dengan benar.

3.4 Expected Result

Sesi pengguna berakhir dan browser diarahkan kembali ke halaman login.

3.5 Troubleshooting

  • Jika pengguna masih bisa membuka halaman tanpa login ulang, hapus cache browser dan refresh.
  • Jika logout tidak merespons, coba muat ulang halaman dan ulangi proses.
4. Dashboard Usage

Penggunaan Dashboard

4.1 Purpose

Menampilkan ringkasan jumlah data dan status operasional yang dibutuhkan pengguna untuk pemantauan cepat.

4.2 Preconditions

  • Pengguna sudah login.
  • Data dasar telah tersedia di sistem.

4.3 Steps

  1. Buka menu Dashboard setelah login.
  2. Periksa kartu ringkasan jumlah data SIMAN, data internal, data invalid, dan status komparasi.
  3. Gunakan filter Unit Kerja untuk melihat kondisi barang berdasarkan unit tertentu.
  4. Klik tautan menu yang tersedia pada kartu ringkasan untuk membuka modul terkait.
Placeholder gambar
  • Screen: Halaman dashboard utama setelah login.
  • Action: Pengguna meninjau kartu ringkasan, filter Unit Kerja, dan tautan laporan.
  • Why: Menjelaskan tampilan utama aplikasi yang menjadi pusat navigasi harian pengguna.
Placeholder gambar
  • Screen: Dashboard saat filter Unit Kerja dipilih.
  • Action: Pengguna mengubah pilihan unit untuk memperbarui angka kondisi barang.
  • Why: Membuktikan bahwa dashboard dapat menampilkan ringkasan yang difilter per unit kerja.

4.4 Expected Result

Pengguna melihat ringkasan operasional dan dapat melompat ke modul yang diperlukan.

4.5 Troubleshooting

  • Jika angka tidak berubah setelah filter dipilih, refresh halaman dan coba lagi.
  • Jika tautan laporan tidak terbuka, pastikan pengguna memiliki hak akses ke modul tersebut.
5. Asset Management

Pengelolaan Data Internal

5.1 Purpose

Memungkinkan pengguna mengelola data aset internal, termasuk menambah, mengubah, melihat, menghapus, melampirkan foto, melampirkan dokumen, dan mengekspor data.

5.2 Preconditions

  • Pengguna sudah login.
  • Pengguna memiliki akses ke menu Internal.
  • Data referensi seperti Barang, Satker, Unit Kerja, Lokasi, dan Identitas tersedia bila diperlukan.

5.3 Steps

  1. Buka menu Internal.
  2. Gunakan daftar data untuk menelusuri aset yang sudah ada.
  3. Klik Tambah Data Internal untuk membuat data baru.
  4. Isi data utama aset sesuai form yang tersedia, lalu simpan.
  5. Gunakan menu edit untuk memperbarui data yang sudah tersimpan.
  6. Gunakan menu foto atau dokumen untuk menambahkan lampiran.
  7. Gunakan ekspor internal bila diperlukan untuk laporan Excel.
  8. Gunakan BAST bila diperlukan untuk dokumen PDF aset.
Placeholder gambar
  • Screen: Halaman daftar data internal.
  • Action: Pengguna meninjau daftar aset sebelum memilih tambah, ubah, atau hapus.
  • Why: Menunjukkan lokasi kerja utama untuk pengelolaan aset internal.
Placeholder gambar
  • Screen: Form tambah data internal.
  • Action: Pengguna mengisi data aset baru lalu menyimpan.
  • Why: Menunjukkan field yang harus dilengkapi saat membuat data aset baru.
Placeholder gambar
  • Screen: Form edit data internal.
  • Action: Pengguna memperbarui informasi aset yang sudah ada.
  • Why: Penting untuk mendokumentasikan bagaimana perubahan data dilakukan pada aset lama.
Placeholder gambar
  • Screen: Area unggah foto atau dokumen pada detail aset.
  • Action: Pengguna menambahkan lampiran pada data aset.
  • Why: Lampiran adalah bukti visual dan administratif yang penting bagi proses verifikasi aset.

5.4 Expected Result

Data aset tersimpan, dapat dicari di daftar internal, dan lampiran tampil pada data terkait.

5.5 Troubleshooting

  • Jika data tidak tersimpan, periksa pesan validasi dan lengkapi field wajib.
  • Jika lampiran gagal diunggah, pastikan file sesuai tipe dan ukuran yang diizinkan.
  • Jika data terkunci, lakukan perubahan hanya bila status data memungkinkan.
6. Import SIMAN

Pengolahan Data SIMAN

6.1 Purpose

Memasukkan data SIMAN dari file CSV untuk dibandingkan dengan data internal dan dianalisis sebagai batch.

6.2 Preconditions

  • Pengguna sudah login.
  • Pengguna memiliki akses ke menu SIMAN.
  • File CSV tersedia dan sesuai format yang dipakai sistem.

6.3 Steps

  1. Buka menu SIMAN.
  2. Klik Tambah Data SiMAN atau menu upload data yang tersedia.
  3. Pilih file CSV SIMAN dari komputer.
  4. Isi label batch jika diminta.
  5. Jalankan proses impor dan tunggu hasilnya.
  6. Periksa hasil impor pada daftar SIMAN dan datatable.
Placeholder gambar
  • Screen: Halaman daftar SIMAN sebelum upload.
  • Action: Pengguna memulai proses impor dari menu SIMAN.
  • Why: Menunjukkan titik awal proses input data SIMAN agar alur dokumentasi jelas.
Placeholder gambar
  • Screen: Form upload CSV SIMAN.
  • Action: Pengguna memilih file dan menjalankan impor.
  • Why: Penting untuk menunjukkan file source yang diproses sistem.

6.4 Expected Result

Data SIMAN tersimpan sebagai batch dan dapat digunakan untuk komparasi dan laporan.

6.5 Troubleshooting

  • Jika impor gagal, periksa kembali format CSV dan kolom wajib.
  • Jika sistem menolak file duplikat, tunggu proses selesai atau gunakan file yang berbeda.
  • Jika ada data yang dilewati, tinjau hasil impor untuk melihat baris yang bermasalah.
7. Reports

Laporan dan Ekspor

7.1 Purpose

Memberikan hasil ringkasan dan file ekspor yang dapat digunakan untuk analisis, pelaporan, dan distribusi dokumen.

7.2 Preconditions

  • Pengguna sudah login.
  • Data sudah tersedia pada modul terkait.
  • Pengguna mengetahui jenis laporan yang ingin dibuka atau diekspor.

7.3 Steps

  1. Buka dashboard, comparison page, activity logs, internal data, invalid data, atau PSP sesuai laporan yang diperlukan.
  2. Tentukan filter yang ingin dipakai, misalnya batch, status, user, atau rentang tanggal.
  3. Klik tombol ekspor yang tersedia untuk menghasilkan file Excel atau PDF.
  4. Simpan atau buka file hasil unduhan sesuai kebutuhan operasional.
Placeholder gambar
  • Screen: Halaman laporan sebelum ekspor.
  • Action: Pengguna memilih filter dan tombol ekspor.
  • Why: Menunjukkan titik pengambilan laporan agar prosedur mudah diulang oleh pengguna akhir.
Placeholder gambar
  • Screen: File hasil ekspor setelah proses selesai.
  • Action: Pengguna membuka atau menyimpan file yang dihasilkan.
  • Why: Menjadi bukti hasil akhir bahwa laporan berhasil dibuat.

7.4 Expected Result

Pengguna memperoleh file laporan yang sesuai dengan data dan filter yang dipilih.

7.5 Troubleshooting

  • Jika file tidak terunduh, periksa pop-up blocker atau hak akses browser.
  • Jika data tidak sesuai filter, ulangi proses dengan parameter yang benar.
  • Jika file PDF kosong, pastikan data yang dipilih memang tersedia.
8. Invalid Data

Penanganan Data Invalid

8.1 Purpose

Memungkinkan pengguna meninjau data yang gagal validasi, memperbaikinya, atau menghapusnya bila tidak diperlukan lagi.

8.2 Preconditions

  • Pengguna sudah login.
  • Data invalid sudah tersedia di sistem.

8.3 Steps

  1. Buka menu Invalid Data.
  2. Gunakan daftar untuk meninjau data yang bermasalah.
  3. Buka baris data untuk diperbaiki bila data dapat diselamatkan.
  4. Simpan perubahan agar data dipindahkan ke data internal jika memenuhi syarat.
  5. Hapus data invalid jika memang tidak dipakai lagi.
Placeholder gambar
  • Screen: Halaman daftar data invalid.
  • Action: Pengguna meninjau baris yang gagal masuk ke data internal.
  • Why: Menunjukkan daftar kerja yang dipakai untuk perbaikan data.
Placeholder gambar
  • Screen: Form edit data invalid.
  • Action: Pengguna memperbaiki nilai yang salah.
  • Why: Penting untuk mendokumentasikan koreksi sebelum data dipindahkan.

8.4 Expected Result

Data invalid berhasil diperbaiki menjadi data internal atau dihapus dari daftar invalid.

8.5 Troubleshooting

  • Jika penyimpanan gagal, periksa kembali field wajib dan format angka.
  • Jika data tidak pindah ke internal, pastikan semua informasi penting sudah lengkap.
9. Locked Data

Pengelolaan Data Terkunci

9.1 Purpose

Menampilkan data internal yang berstatus terkunci dan memungkinkan proses request unlock, unlock, atau reject request sesuai hak akses.

9.2 Preconditions

  • Pengguna sudah login.
  • Pengguna memiliki akses ke menu terkait locked data.

9.3 Steps

  1. Buka menu Locked Data.
  2. Gunakan filter untuk mencari data berdasarkan unit kerja, lokasi, kategori, atau status request.
  3. Buka detail data yang dibutuhkan.
  4. Lakukan lock, unlock, request unlock, atau reject request sesuai hak akses dan kondisi data.
Placeholder gambar
  • Screen: Halaman locked data.
  • Action: Pengguna melihat data yang berstatus locked dan memeriksa status request.
  • Why: Menjelaskan area kontrol data yang tidak lagi dapat diubah bebas oleh pengguna biasa.
Placeholder gambar
  • Screen: Tombol lock, unlock, request unlock, atau reject request pada baris data.
  • Action: Pengguna menjalankan aksi status pada data tertentu.
  • Why: Membuktikan lokasi aksi penguncian yang digunakan dalam proses kontrol aset.

9.4 Expected Result

Status data berubah sesuai aksi yang dipilih dan tampilan daftar diperbarui.

9.5 Troubleshooting

  • Jika tombol tidak tersedia, periksa peran pengguna.
  • Jika data tidak berubah status, muat ulang halaman dan ulangi aksi.
10. Settings

Pengaturan Sistem

10.1 Purpose

Memperbarui data pengaturan yang dipakai pada dokumen PSP dan informasi administratif lain yang ditampilkan sistem.

10.2 Preconditions

  • Pengguna administrator sudah login.
  • Pengguna memiliki hak akses ke halaman Settings.

10.3 Steps

  1. Buka menu Settings.
  2. Periksa nilai yang ada seperti admin phone, biro, NIP biro, kepada, jabatan, dan lokasi.
  3. Ubah nilai yang diperlukan sesuai data terbaru.
  4. Simpan perubahan.
Placeholder gambar
  • Screen: Halaman Settings.
  • Action: Administrator meninjau dan mengubah nilai pengaturan.
  • Why: Menunjukkan area administrasi yang memengaruhi isi dokumen dan kontak sistem.

10.4 Expected Result

Nilai pengaturan tersimpan dan digunakan oleh modul yang bergantung pada data tersebut.

10.5 Troubleshooting

  • Jika penyimpanan gagal, periksa batas panjang field atau pesan validasi.
  • Jika data tidak berubah di dokumen, buka ulang halaman untuk memastikan perubahan tersimpan.
11. User Management

Manajemen Pengguna

11.1 Purpose

Memungkinkan administrator menambah, memperbarui, dan menghapus akun pengguna sistem.

11.2 Preconditions

  • Administrator sudah login.
  • Menu User tersedia pada role administrator.

11.3 Steps

  1. Buka menu User.
  2. Klik Create User untuk menambahkan akun baru.
  3. Isi nama, email, password, level akses, dan unit kerja bila diperlukan.
  4. Simpan data pengguna.
  5. Gunakan menu edit untuk memperbarui data pengguna yang sudah ada.
  6. Gunakan menu hapus untuk menghapus pengguna yang tidak dipakai lagi.
Placeholder gambar
  • Screen: Daftar pengguna.
  • Action: Administrator meninjau akun yang ada sebelum menambah atau mengubah data.
  • Why: Menunjukkan lokasi utama pengelolaan akun dalam sistem.
Placeholder gambar
  • Screen: Form tambah pengguna.
  • Action: Administrator mengisi data akun baru dan memilih level akses.
  • Why: Penting untuk mendokumentasikan pengaturan akun baru dan hak aksesnya.
Placeholder gambar
  • Screen: Form edit pengguna.
  • Action: Administrator memperbarui data akun yang ada.
  • Why: Menunjukkan cara perubahan data pengguna dilakukan secara operasional.

11.4 Expected Result

Data pengguna tersimpan dan dapat digunakan untuk login sesuai level aksesnya.

11.5 Troubleshooting

  • Jika email sudah terdaftar, gunakan email lain.
  • Jika password tidak diterima, pastikan minimal 6 karakter dan konfirmasi cocok.
  • Pengguna admin bawaan bernomor ID 1 tidak dapat diubah atau dihapus berdasarkan kode sumber.
12. CRUD Operations / Master Data

Pengelolaan Data Referensi

12.1 Purpose

Memelihara data referensi yang dipakai oleh modul operasional, seperti BMN, satker, barang, lokasi, identitas kategori, identitas, atribut, unit kerja, dan unit teknis.

12.2 Preconditions

  • Administrator sudah login.
  • Data referensi dapat diakses melalui menu master data masing-masing.

12.3 Steps

  1. Buka menu master data yang ingin dikelola.
  2. Klik Create untuk menambah data referensi baru.
  3. Isi form sesuai jenis data referensi.
  4. Simpan data.
  5. Gunakan Edit untuk mengubah data yang sudah tersimpan.
  6. Gunakan Delete untuk menghapus data yang tidak lagi dipakai.
Placeholder gambar
  • Screen: Salah satu halaman master data, misalnya BMN atau Barang.
  • Action: Administrator membuka daftar referensi sebelum melakukan tambah, ubah, atau hapus.
  • Why: Menunjukkan pola CRUD yang dipakai di seluruh menu referensi.
Placeholder gambar
  • Screen: Form tambah master data.
  • Action: Administrator menambahkan referensi baru.
  • Why: Membantu pengguna memahami cara mengisi data referensi yang menjadi dasar transaksi.

12.4 Expected Result

Data referensi tersimpan dan dapat dipakai oleh modul lain seperti internal, SIMAN, dan PSP.

12.5 Troubleshooting

  • Jika nama sudah ada, gunakan nilai yang unik sesuai pesan validasi.
  • Jika data tidak dapat dihapus, periksa apakah data masih digunakan oleh relasi lain.
13. Backup Management

Manajemen Cadangan

13.1 Purpose

Menjalankan, memantau, mengunduh, dan menghapus file cadangan aplikasi.

13.2 Preconditions

  • Administrator sudah login.
  • Menu Backups tersedia.

13.3 Steps

  1. Buka menu Backups.
  2. Periksa daftar file backup yang tersedia.
  3. Klik Full Backup untuk menjalankan cadangan lengkap.
  4. Klik Files Only jika hanya ingin mencadangkan file.
  5. Gunakan tombol Download untuk mengambil file backup tertentu.
  6. Gunakan tombol Delete bila file backup sudah tidak diperlukan.
Placeholder gambar
  • Screen: Halaman backup management.
  • Action: Administrator meninjau daftar backup dan memilih tindakan.
  • Why: Menunjukkan area operasional untuk perlindungan data sistem.

13.4 Expected Result

File backup dapat dibuat, diunduh, atau dihapus sesuai kebutuhan administrasi.

13.5 Troubleshooting

  • Jika file tidak ditemukan, pastikan backup sudah berhasil dibuat.
  • Jika unduhan gagal, cek izin akses dan ketersediaan file pada folder backup.
14. Activity Log Review

Peninjauan Log Aktivitas

14.1 Purpose

Memeriksa riwayat aktivitas pengguna, mengekspor log, dan membersihkan log lama bila diperlukan.

14.2 Preconditions

  • Administrator atau pengguna yang diberi akses sudah login.
  • Log aktivitas sudah tersedia di database.

14.3 Steps

  1. Buka menu Activity Logs.
  2. Gunakan filter berdasarkan user, metode, atau tanggal bila diperlukan.
  3. Buka detail log untuk melihat URI, route, parameter, status code, dan user agent.
  4. Klik Export untuk mengunduh log dalam format Excel.
  5. Klik Cleanup untuk menghapus log yang sangat lama sesuai kebijakan sistem.
Placeholder gambar
  • Screen: Halaman Activity Logs.
  • Action: Pengguna meninjau daftar log dan menerapkan filter.
  • Why: Membantu audit operasional dan menelusuri tindakan pengguna.
Placeholder gambar
  • Screen: Detail satu log aktivitas.
  • Action: Pengguna membuka rincian log untuk investigasi.
  • Why: Memperlihatkan informasi detail yang dipakai saat audit atau penelusuran insiden.

14.4 Expected Result

Pengguna mendapatkan visibilitas atas aktivitas aplikasi dan dapat mengekspor log bila diperlukan.

14.5 Troubleshooting

  • Jika tabel kosong, pastikan ada data yang cocok dengan filter.
  • Jika ekspor gagal, coba ulangi setelah filter disederhanakan.
15. PSP Document Generation

Generasi Dokumen PSP

15.1 Purpose

Membuat dokumen PSP dalam format PDF berdasarkan data internal yang dipilih dan data pengaturan yang disimpan di sistem.

15.2 Preconditions

  • Administrator sudah login.
  • Data internal yang akan diproses sudah tersedia.
  • Pengaturan biro, NIP biro, kepada, jabatan, dan lokasi sudah diisi bila diperlukan.

15.3 Steps

  1. Buka menu PSP.
  2. Pilih data internal yang akan dimasukkan ke dokumen.
  3. Isi lampiran bila diperlukan.
  4. Gunakan tombol unduh atau generate untuk membuat PDF PSP.
  5. Simpan file PDF yang dihasilkan.
Placeholder gambar
  • Screen: Halaman PSP sebelum pemilihan data.
  • Action: Administrator memilih data internal yang akan dicetak ke PDF.
  • Why: Menunjukkan sumber data yang digunakan untuk menghasilkan dokumen PSP.
Placeholder gambar
  • Screen: Hasil PDF PSP yang terbuka atau terunduh.
  • Action: Administrator memeriksa dokumen hasil generate.
  • Why: Penting untuk memverifikasi isi dan format dokumen sebelum dipakai resmi.

15.4 Expected Result

File PDF PSP berhasil dibuat dengan data yang dipilih dan siap digunakan.

15.5 Troubleshooting

  • Jika PDF kosong, pastikan data internal yang dipilih memang ada.
  • Jika hasil dokumen tidak sesuai, cek kembali pengaturan biro dan lokasi.
